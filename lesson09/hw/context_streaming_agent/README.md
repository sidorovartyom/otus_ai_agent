# Домашнее задание 9: подключение контекста и streaming

## Что реализовано

1. **Источник контекста** — `knowledge_base.md`, локальный файл с базой
   знаний вымышленного сервиса Otus Cloud (тарифы, SLA, поддержка,
   миграция). Факты в нём намеренно не пересекаются с тем, что модель
   могла бы знать сама, — это позволяет однозначно увидеть в демо, что
   ответ построен на подключённом контексте, а не на догадках модели.
2. **Подключение контекста к агенту** — `context_source.get_context()`
   читает файл и возвращает его текст; `agent.py` подставляет этот текст
   в system-промпт перед каждым запросом к LLM.
3. **Streaming ответа** — `agent.stream_reply()` использует
   `client.messages.stream(...)` и построчно печатает `stream.text_stream`
   по мере поступления фрагментов от API.
4. **Сценарий взаимодействия** — `demo.py`: 4 вопроса подряд в одном
   диалоге (история накапливается в `messages`), включая один вопрос,
   ответа на который в базе знаний нет — так видно, что агент не
   выдумывает факты, а честно опирается на контекст.

## Архитектура подключения

```
┌─────────────────────┐
│ knowledge_base.md    │  (источник контекста: файл)
└──────────┬────────────┘
           │ .read_text()
           ▼
┌─────────────────────┐
│ context_source.py     │  get_context() -> str
│  get_context()         │  (единственная точка подключения контекста;
└──────────┬────────────┘   чтобы заменить файл на API, меняется
           │                только это место, см. ниже)
           │ строка контекста
           ▼
┌─────────────────────────────┐
│ agent.py                       │
│ SYSTEM_PROMPT_TEMPLATE.format( │  контекст встраивается в system-промпт
│   context=...)                  │  на каждый вызов (без сохранения
└──────────┬──────────────────┘  состояния между процессами)
           │ client.messages.stream(system=..., messages=...)
           ▼
┌─────────────────────────────┐
│ Anthropic API (корп. прокси)   │  HTTP + SSE (Server-Sent Events) -
│ .env: AUTH_TOKEN/BASE_URL/CERT │  тот же принцип, что в референсном
└──────────┬──────────────────┘  репо Webinar8.sse из материалов урока
           │ поток text-дельт
           ▼
┌─────────────────────────────┐
│ demo.py: on_delta -> print()   │  дельты печатаются сразу, полный
│ messages.append(assistant)     │  ответ накапливается для истории
└─────────────────────────────┘
```

Ключевая граница интерфейса — функция `get_context()`. `agent.py` ничего
не знает о том, что источник контекста — файл; он лишь вызывает функцию,
возвращающую строку.

### Как подключить контекст из API вместо файла

Заменить реализацию `get_context()` в `context_source.py`, не трогая
`agent.py` и `demo.py`:

```python
import httpx

def get_context(topic: str | None = None) -> str:
    resp = httpx.get("https://internal-kb.example/api/context", params={"topic": topic})
    resp.raise_for_status()
    return resp.json()["text"]
```

## Запуск

Из папки `lesson09/hw` (после того, как в корне репозитория настроен
`.env` — тот же файл, что используется в lesson04 и lesson06):

```bash
python -m context_streaming_agent.demo
```

`agent.py` сам определяет, какой пакет нужен для `http_client` (`httpx`
или `httpx2` - в некоторых окружениях SDK ожидает именно `httpx2`), так
что команда работает и с глобальным Python, и с venv репозитория.

Ожидаемое поведение: для каждого из 4 вопросов текст ответа агента
печатается постепенно, по мере генерации (а не одним блоком после паузы),
и последний ответ честно указывает, что стоимости переноса 500 ГБ в базе
знаний нет.
